# CCTSystem 桥接超时排查与修复（2026-10-06）

## 现场证据与边界

会员请求链路是子服 CCTSystem → Cloudflare Worker / BridgeCoordinator → 会员业务节点 → Worker → 子服。官网会员接口明确指定 MEMBERSHIP_SERVER_ID=lobby；原先游戏发起的会员请求没有指定 serverId，Lobby2 与 Creative2 都声明了 business-authority，实际选择会受连接建立时间影响。这次统一指定配置中的会员业务服，不再由其他节点的重连改变会员路由。

多个实例日志都有 heartbeat timeout、1006、HTTP connect timeout，随后自动重新连接。服务器访问桥接 HTTP 地址时，IPv4、IPv6 都实际出现过 TLS 握手阶段超时；另一些请求正常完成。因此网络瞬时不稳定是已观察到的事实，但尚不能确定具体运营商、Cloudflare 边缘或中间设备是根因，不能宣称代码修复会消除网络波动。

原先 Java 桥接的 call、hello、response、heartbeat 各自直接 sendText，序号也在发送之前分别分配。新增回归测试模拟发送尚未完成时有 100 个并发请求，验证新队列仅允许一个文本发送进行，序号与实际发送顺序一致。并发发送是确认存在的实现风险，尚无生产日志证明所有历史断线都由它触发。

## 实际改动

- 每条连接使用独立的发送队列，在同一队列分配序号；发送失败清理等待请求、断开旧连接并重连，旧连接的迟到消息不污染新连接状态。
- 已过期的入站 RPC 立即返回 REQUEST_EXPIRED，不执行操作，不以“无效消息”告警后继续让调用者空等。
- Worker 会员请求使用配置指定的大厅；不向超过 65 秒未活动的节点派发 RPC；转发为返回结果预留 250 毫秒，不延长原请求的预算。
- Worker 异步转发异常返回明确失败结果并保留错误日志；超时记录 INFO，包括目标节点、操作和请求编号，便于分辨本地等不到 Worker 与 Worker 等不到业务节点。
- 登录后会员查询遇到明确的临时桥接错误，最多延迟重试两次（5 秒、10 秒），执行前确认玩家在线；购买、扣款不自动重试。
- 桥接临时断线、连接超时、会员查询/菜单的临时桥接故障使用 INFO 状态日志，不再打印 WARN 异常堆栈。身份冲突、无效响应、认证握手失败、协议错误和程序错误保留告警。

## 验证

新增 9 项回归测试通过，覆盖并发发送、发送失败、过期请求、旧连接消息、日志分级、失活节点、错误回包、会员路由与返回预算。Java 相关模块执行 21 项测试；12 项依赖外部数据库的既有集成测试按原条件跳过。Worker 全部 40 项测试及 TypeScript 类型检查通过，插件打包成功。

Worker 发布版本：8e41291c-17dc-4923-a6eb-e4e81498ca33。
